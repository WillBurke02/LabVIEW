Preface

 

With example as follows, we aim to teach you the best and simple way of using Data Acquisition Functions of our USPC card as well as getting under control all tricks and variable for setting them up properly.

 

To illustrate those technique, we will study an ultrasonic testing application with immersion tank.

Step by step, we will approach each acquisition mode such as:

-          N points acquisition (stage 1),

-          Continuous acquisition (stage 2),

-          Trigger control acquisition (stage 3).

 

Immersion tank application

 

Our example will use a 3 axes (X-Y-Z) manipulator for testing flat parts in immersion. Scanning plan is always defined as X-Y; scanning axis is X, stepping axis is Y and Z axis for water gap setup.

Application will allow displaying, in real time, A-scan signal and recording/displaying Amplitude & TOF C-scan in Gate 1 and 2.

Stage 1 : N points acquisition

 

(Uspc acq example step1.gif)

First of all, application software must open an access to USPC card (PCXUS_Open), and load the ultrasonic setting file or UT file (PCXUS_Load). Then we will select “External synchro.” mode in order data acquisition to be triggered from X axis scanning.

 

Trick : when creaating UT file, select « Internal synchro. » in “Pulser” function, thus you will be able setting UT parameters with active A-scan signal without X axis to be necessary moving on. Immersion tank application software will control “synchro.” mode when running.

 

Remark : we will use X axis encoder signal to trigger data acquisition (connect to USPC card Input PRF IN). If encoder resolution is not the required one for the application, or if you want to use another resolution, you have to use a division processing interface of encoder output ( example : PC card TIO-10 or PCI 6602 from  National Instruments). It is very important than pulsing shots are triggered by scanning axis. This will ensure that distance between two acquisition points is constant and well corresponding to your resolution. Indeed, scanning speed is not constant: speed profile xomes through an acceleration stage (starting scanning), a steady stage and finally a deceleration stage (stopping scanning).

 

Application must run the scanning at the right starting point of control and define the control area. This area can be defined by scanning length, acquisition step resolution, number of scanning, Y axis step resolution and scanning speed.

From all those information we are then able to define the configuration parameters of acquisition.

Stage 2 : Continuous acquisition

 

(Uspc acq example step2.gif)

In previous example, keeping C-scan mapping up-to-date is made at end of scanning line. Think up we want up-to-date C-scan mapping whilst   X axis is moving; This will bring double interest when scanning line is too long:

1 – we do not have to wait for end of scanning to display result.

2 – we can empty DLL memory at regular intervals in order to optimize it.

 

Lets remind us of data transfer principle:

 - data are transferred from USPC card to DLL memory at such a rate defined by “Fluidity” parameter.

 - Then toward application software memory at a rate requested by this application.

 

Bear our interest on one type of data, i.e amplitude in Gate 1; memory size necessary to receive a full scanning line is 32 times less than memory allocated by DLL (one C-scan point is 32 bytes and amplitude is 1 byte).

Example : we want 100 scanning lines and 3000 points per line. If we want acquire all points per line at once, we must allocate a buffer of 3000 C-scans in DLL and application must set an array of 3000 bytes multiplied per 100 lines.

Total necessary memory for this application is then:

3000 C-scan of 32 bytes (used by DLL) = 96 KB

3000 bytes (amplitude) per 100 lines = 300 KB

Total = 396 KB

 

Now cut out a line with packs of 100 points, we can then allocate a smaller buffer (200 for example).

Total necessary memory becomes then:

200 C-scan of 32 bytes (used by DLL) = 6.4 KB

3000 bytes (amplitude) per 100 lines = 300 KB

Total = 306.4 KB

 

NB : This method, consisting in allocating part of memory and in reading it at regular interval, must use a circular buffer. Data are bufferized and when getting to end of it, then data writing get back to buffer start.

 

This method is absolutely necessary when testing long products or products in one continuous stream such as tubes, plate mills, bar mills, casting…

 

Our application will have to read packs of data and display them at regular interval till end of scanning.

Using this method will lead you taking a few precautions. First of all, take care that processing time (display/record) of data packs read is not over than necessary time to acquire those data packs; unlike this buffer will get full and new data will overwrite old ones (overwrite error).

 

Parameters such as:

 - “BufferSize” and “Fluidity” from “PCXUS_ACQ_CONFIG” function,

 - “NumberOfScansToRead” and “ScanBackLog” from “PCXUS_ACQ_READ” function

will allow you to control this time.

 

“ScanBackLog” is the number of remaining points after reading the buffer. When  this number increases, it means processing time is too long, in that case you must increase the number of points to read and/or increase “Fluidity”.

 

“Fluidity” selects the number of points to be transferred from USPC card to buffer. This number determines then the filling speed of buffer (see scheme in section Principe of data transfer).

 

Remark : if you type a negative value in “NumberOfScansToRead” , “PCXUS_ACQ_READ” function will read all points in buffer. Remaining points fram “ScanBackLOg” should be only zero anyway.

 

 

Stage 3 : Trigger-control acquisition

 

(Uspc acq example step3.gif)

Trigger-control acquisition mode can be used in flollowing cases :

 - 1) External signal (ENABLE pin 6) allowing acquisitions.

 - 2) We want to make acquisition only in case of one or several alarms( Alarm +/Alarm -/Min. alarm/Max. alarm…)

 

Remark : both cases 1 & 2 can be combined together.

 

Case 2) allows also to optimize memory size (RAM or hard disk). Lets assume we want to record only data when USPC card detects an echo into Gate, optimising effect should be huge ! when ni defect is detected, then memory size is zero.

 

Quite often, it is interesting to kwon what happening before and after the defect; this possibility is proposed to you when you need recording A-scan data. “Pre-Post trigger” parameter will define the number of A-scan to be recorede before and after trigger occurrences.

 

To pitcher this method, our application will record A-scan when echo overpasses Gate 1 alarm threshold; we will record 10 A-scans before and after alarm detection. This example will likely runs pointers shown in each A-scans. Those pointers allow us positioning each A-scan. Indeed, in previous examples, we were able to figure out position of each point within scanning line (position X of point N = N * scanning step). This is not possible anymore when using trigger-control acquisitions. We will use “pulse_counter” (counter 32 bits) to locate an acquisition point (position X of point N = Pulse_counter(N) * scanning step).
