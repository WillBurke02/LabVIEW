PCXUS_ACQ_CONFIG.htm

Update 21 February 2008

 

Compatibility:

Platforms: Windows 2000/NT4/XP (unsupported on Windows 98)

 

Function:

ULONG WINAPI PCXUS_ACQ_CONFIG(ULONG hPCXUS, int Board, ULONG AcqMode, ULONG StartMode, ULONG AcqCondition[8], int PrePostScans, int FrequencyDivider, ULONG BufferSize, int InterruptFluidity, ULONG *Param)

 

Description:

This function sets acquisition configuration.

 

Arguments:

HPCXUS                       Your access number (see PCXUS_Open function).

 

Board                            Board number to be set up( 0 to 9).

 

AcqMode                      Define acquisition mode

                                               0x800 : Gates (Amplitudes, TOF/WT, Alarms) ,(not supported by version I and MB)

                                               0x1000 : A-Scan and Gates; (A-Scan resolution depends of digitising mode and filter selected),(only for hardware version LA, MBA and MHA(*))         

                                               0x2000 : A-Scan HR;  A-Scan resolution is fixed by FrequencyDivider parameter (gates information excluded) ),(only for hardware version LA).

                                    Remark: Before using AcqMode 2, High resolution must be activated, all gates disabled and PRF must be greater than “Scope offset + 11 * Scope range”.

                                    AcqMode 2 is very useful for FFT processing.

 

StartMode                     Define start mode. After a call to PCXUS_ACQ_START function, the acquisition will start:

                                               1 : Immediately,

                                               3 : Upon external signal (ENABLE pin),

                                               5 : Upon data conditions (conditions are defined by AcqCondition[] parameter),

                                               7 : Upon external signal (ENABLE pin) and data condition.

Tip for MUX: If you want to acquire all channels with only one condition on particular channel, you have to set StartMode=7 and assign the condition on a pin and connect it on ENABLE pin.

 

AcqCondition[8]             Define acquisition condition if StartMode equal 5 or 7 (for each channel when using MUX)

                                               1 : Coupling alarm Gate 1,

2 : Alarm Gate 1,

4 : TOF/WT alarm maxi Gate 1,

8 : TOF/WT alarm mini Gate 1,

                                               16 (10 H): Coupling alarm Gate 1,

32 (20 H): Alarm Gate 2,                      

64 (40 H): TOF/WT alarm maxi Gate 2,

128 (80 H): TOF/WT alarm mini Gate 2,

512 (200 H):  Alarm Gate IF,

1023(3FF H) : NO condition.

Remark:

·         You can combine several conditions.

o        For example: Alarm Gate 1 AND Alarm Gate 2 => 2 + 32 = 34.

·         Combination could be AND or OR logic: add (4096)1000H to combine alarm with OR logic. (New  from version 6.4.3)

o        Alarm Gate 1 AND Alarm Gate 2 => 2 + 32 = 34.

o        Alarm Gate 1 OR Alarm Gate 2 => 2 + 32  + 4096= 4130  

 

 

PrePostScans               Define number of A-Scans stored before and after condition occurs(0 to 32)(0 to 7 for MBA and MHA boards (*)).

                                    This parameter is ignored if no condition is defined or AcqMode not equal to A-Scan mode.

                                    This parameter is very useful when storing A-Scans as they fill a lot of memories. Most of the time, only A-Scans before, during and after condition occurs, are interesting.

                                   

FrequencyDivider           Define digitising resolution for A-Scan HR (required AcqMode=2) (1 to all even figures till 128)

                                    1: 100 MHz,

                                    2: 50 MHz,

                                    4: 25 MHz,

                                    8: 12.5 MHz,

                                    …

 

BufferSize                     Define the maximum number of Scans into the buffer.

The buffer is a circular buffer. If the buffer is full then new data are written at the beginning of buffer (Overwrite error occurs)

 

*InterruptFluidity             Define number of Scans to be transferred  from USPC to PC memory  (1 to “NumberOfScans”).

                                    This parameter is important to give CPU time for others tasks.

                                    The transfer between USPC and PC uses Bus master mode (need no CPU time). But to initiate the transfer, a CPU time is required.

                                    To use the minimum of CPU time, it is better to transfer a large size of data.

                                    This parameter must respect following conditions:

1.       InterruptFluidity >= 1

2.       InterruptFluidity <= BufferSize/2

3.       For C-scan

LA/MBA/MHA/MHA+

LC/MBC/MHC/MHC+

InterruptFluidity max. = 8192

InterruptFluidity max. = 512

 

4.       For A-scan. InterruptFluidity max. = 464

5.       For A-scan HR. InterruptFluidity max. = 65536 / ( 16 + (scope range/ resolution) modulo 4))

6.       The number of transfers per second < 50. (PRF * InterruptFluidity > 20ms)

 

Param                           Reserved for extension.

 

Returns:

0                      no error

0x80000100      board number error

0x80000C00      access number error

0x80000C08      access number error (this board is configured by another application) (This error code is managed since DLL 10.0.0)

0x80000000      undefined error

0x80000001      configuration memory error

0x80000002      acquisition mode error

0x80000003      start mode error

0x80000004      start condition error

0x80000005      pre-post trigger error

0x80000006      frequency divider error

0x80000007      buffer size error

0x80000008      configuration already exist

0x80000009      buffer read/ write operation error

0x8000000A      get size of scans error

0x80000014      Interrupt fluidity error

0x80000015      A-scan HR mode error (high resolution is requested)

0x80000017      A-scan HR mode error (all gates must be inactivated)

0x80000018      PRF error (PRF is too fast)

0x80000020      Display mode error (Snapshot is requested)

 

*InterruptFluidity  This parameter is updated to maximum value if it was too large

 

Special timing consideration:

The PRF must be respect some rules to enable acquisition process (see PRF rules).

 

Remark: During acquisition cycle on each transfer between USPC board and DLL one Ascan for the display is transferred.

So the maximum number of Ascan per second, readable by PCXUS_ACQ_ASCAN, is fixed by the PRF and Interrupt fluidity (max 50 A-scans/sec).

 

 (*) MBA and MHA are supported since DLL version 8.0.0
